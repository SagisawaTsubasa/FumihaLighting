# Fumiha Lighting 文羽照明

恒照度补偿（原 lux_balance）与定时夜灯组（原 auto_night_light）的合并集成。一个 domain、两种条目类型、两个文羽面板页面；页面读写走集成自有 REST，实体（light/number/button/sensor）只作为 HA 原生生态（自动化/仪表盘）的适配层。

## 从旧集成迁移（一次性）

1. HACS 添加并安装 `SagisawaTsubasa/FumihaLighting`，重启 HA
2. **删除**旧条目：设置 → 设备与服务 → lux_balance 条目、auto_night_light 条目 → 删除
3. **删除**旧集成本身（HACS 里移除 lux_balance / auto_night_light，或先留着不冲突）
4. 添加「Fumiha Lighting 文羽照明」→ 选择类型：
   - **恒照度区域**：填区域名、灯、照度传感器（同旧 lux_balance 配置）
   - **夜灯组**：按向导填时间锚点/灯/参数（同旧 auto_night_light 配置）
5. 卫生间区**重新校准一次**（曲线不迁移；默认 5% 步长约 15~40 分钟，上报不畅最坏约 1 小时 20 分；2%/3% 细扫最坏可能 2~3 小时）

已知破坏面：服务改名 `fumiha_lighting.calibrate` / `fumiha_lighting.trigger_now`；实体 platform 变更导致 entity_id 重建（引用旧实体 id 的自动化需改）。

## 架构

- 页面（文羽面板壳内 `luxbalance.main` / `anl.main` 两个页签；壳缺席时各自回落独立侧边栏面板）
- REST：`GET /api/fumiha_lighting/lux/overview`、`GET /api/fumiha_lighting/anl/snapshot`；写：`POST /api/fumiha_lighting/lux/target|calibrate|calibrate/cancel`、`POST /api/fumiha_lighting/anl/trigger`、`GET|POST /api/fumiha_lighting/anl/config`（夜灯设置读写，V1.4.0）
- 服务（自动化面）：`fumiha_lighting.calibrate`（目标未命中/互斥跳过时抛错）、`fumiha_lighting.trigger_now`
- `static/kit.js`、`static/tokens.css` 为 FumihaHub vendored 副本（锁步更新）

## 夜灯组配置（V1.4.0 起）

**原生向导只保留 3 步**：选择灯具 → 时间锚点（开始/结束方式 + 固定时间/偏移 + 太阳实体 + 过渡时长，一页）→ 全局参数（夜间/日间亮度色温、容差、延迟、行为开关）。

**逐灯覆盖与额外时段在「夜灯助手」页面编辑**（点条目卡「⚙ 设置」或灯卡「逐灯设置」）：

- 全局设置弹窗：时间锚点、全部参数、额外时段增删改（0–5 个），保存经 `POST /api/fumiha_lighting/anl/config` 写入条目 options，自动重载生效；
- 逐灯设置弹窗：「跟随全局」开关 + 夜间/日间/各额外时段参数覆盖，取消覆盖即恢复全局；
- 校验与向导共用同一份字段规格（`anl/config_schema.py`），越界/未知灯/超时段数都会被 400 拒绝。

HA 原生「配置」（options 流）与向导同字段同存储，同样不含逐灯覆盖/额外时段。语义注记：**重新配置**（reconfigure）保存时会把条目数据整体收敛进 `data` 并清空 `options`，GUI 写入的额外时段/逐灯覆盖会原样携带，不会丢失。

### 日间恒照度模式（V1.5.0 引入，V1.6.0 单灯化）

日间段恒照度接管（CI）为**逐灯开关**：`day_ci_lights` 表达「组内哪些灯归恒照度接管」，全局 `day_ci_enabled` 键废除（存量条目读入迁移：旧键 true → 灯集全集，零回写）。被接管的灯日间**不直控亮度**，改为驱动恒照度（lux）侧该灯所属区域的虚拟恒照度灯实体——开虚拟灯 = lux 闭环接管（联动 `light.turn_on` 绝不带亮度，带亮度会落 lux passthrough 破坏闭环）。**V1.7.0 起 `day_ci_virtual_light` 配置键废除**：移交对象由系统按「灯 → 恒照度区域」反查表推导，不由用户指定（清单内灯不属于任何区域 → WARNING 每 夜灯组一次 + 运行时跳过该灯，保留存储）。接管时机为**事件驱动**：

- 白天开 CI 接管灯（开灯监听）或触发落在日间 → 开其所属区域的虚拟灯交恒照度闭环，CI 灯真实灯零亮度下发、无 settle 延迟；**非 CI 灯日间照常**（日侧过渡带、日间参数下发、逐灯日间覆盖全部照旧）；
- 夜间开始锚点触发（或触发落在夜间/额外时段）→ 先按清单推导的区域集合逐区归还虚拟灯（lux off = 纯放手，对真实灯零下发），再按夜灯参数直控；
- **色温补发（B1）**：移交开始按该灯日间色温参数（含逐灯日间覆盖）对真实灯一次性下发（仅 color_temp_kelvin，不与亮度闭环冲突）——接管时段不再「亮度归闭环、色温停在夜间暖光」；
- CI 接管灯的日间**亮度**不生效（闭环管）；逐灯日间色温覆盖随补发复活；日侧过渡带只对非 CI 灯生成步进，夜间↔额外时段过渡不受影响；
- 虚拟灯服务失败 → WARNING（每夜灯组节流一次）+ 该灯回落日间参数直控，错误必响但保可用；
- 一轮触发对每个 involved 区域的虚拟灯至多一次 turn_on/turn_off（按 zone 轮级去重）；「仅调整已开启的灯」按灯准入——全部 CI 接管灯关着时不开虚拟灯，多区组只 ensure 有灯亮着的区（关着的区不被经 lux 点亮）；
- **A3 防护**：夜灯对属于恒照度区域的灯任何直控（触发/监听 settle/额外时段/计划步）前，若其闭环在跑（active/passthrough）先归还再直控——夜间锚点直控 lux 区灯「整夜互纠」的根治。

CI 的编辑入口（V1.6.1 起）在夜灯助手页面的**逐灯设置弹窗**（「日间恒照度接管」开关），开关按区域归属三态（首审修复后）：已勾选且属于区域 → 标注「由恒照度区域 X 接管」；属于区域但未勾选 → 可勾选并提示「勾选后由该区闭环接管」（接管唯一新开入口）；不属于任何区域 → 禁用并提示，存量勾选但区域已删的灯保持可取消。全局设置弹窗零 CI 配置（虚拟灯行已删除）；向导不配 CI。REST 侧校验：**新增**清单灯必须属于某个恒照度区域（400 逐灯报名；存量失效项放行，运行时 WARNING+跳过——整表校验遇多条失效项会互锁），day_ci_virtual_light 键按死键清理。

### 恒照度联动组与控制权反查表（V1.7.0 合并批）

多灯同房间（如卫生间干湿区）各自闭环时，对方的补偿会被本区当成环境扰动，通过物理空间耦合互相拉锯（实测 3 分钟 14 次决策横跳）。联动组把同房间条目组成一个照明空间，ambient 计算扣除组内其他灯的贡献，各组互不干扰、各维持各的目标照度。

**建组**：亮度均衡页面 zone 卡的联动组 chip 点击即编辑（V1.7.1 面板内入口：组标签 + 交叉系数 + 缓变步幅 + 组内成员名单——三键此前藏在 options 流第 2 页「校准与降级」，保存后自动重载生效）；原生入口仍在条目「配置」（options 流）。组标签填同一自由文本（如「卫生间」）即互认为同组；留空停用。

**交叉校准**：校准任一区（X）时，同组其他区（Y）的传感器自动同步采样——X 的 sweep 完成、主曲线采纳后，为每个 Y 产出「X 灯 → Y 传感器」交叉曲线（与主曲线同一组合管线，存储进 Y 条目）。同组一次只能校准一个区（其余区闭环自动让路），两条目**各跑一次校准**即完成双向交叉曲线。主曲线校准失败时交叉采样一并废弃，不产出半截曲线；某区交叉曲线缺失（质量门不达/缺基线）时该区运行时按近似系数兜底，页面不谎报。

**近似系数**（cross_fade，0.1~1.0 默认 0.5）：无交叉曲线时按「对方主曲线 × 系数」估算对方对本传感器的贡献。校准质量差或灯与传感器阻隔强的房间可调低。

**亮度缓变**（max_step_pct，5~50 默认 20）：闭环单次决策的亮度变化上限，大幅修正分多步逼近，消除单步大跳；关灯决策不受限。

**与夜灯模组协调**（V1.3.0 开关语义）：恒照度条目的映射实体（虚拟灯）即闭环总开关——**关闭映射实体 = 集成彻底放手**：不下发关灯（原灯归用户/夜灯模组，纯放手不牵连）、外部开灯（夜灯/手动）不触发接管、重启后不自动恢复（等映射实体重新打开）。夜灯模组的映射实体开关同理互不干扰，两模组通过各自的映射实体开关划分控制权。

**灯 → 区域反查表**（V1.7.0 A 面，A1/A2/A3/B2 三面共用）：`light_registry.build_light_zone_index` 实时遍历 lux 条目构建「真实灯 entity_id → 区域（entry_id/zone_name/虚拟灯）」映射，无缓存失效面（lux 条目卸载即刻失效，消费端按「不属于任何恒照度区域」跳过）。三面消费：CI 推导（上文）、lux 配置查重（**一盏灯只能属一个区域**——同灯换传感器再建区域在保存时拒绝「该灯已属恒照度区域 X」）、夜灯直控防护（上文 A3）。R1 首审修复随批：联动监听对称化（先启动的区也能听到后加入的组员）、开灯首帧与闭环主路径共用同一照度判据（中值滤波+交叉贡献扣除+照度死区）、亮度未知三态统一（不贡献亦不限幅）、交叉曲线损坏响亮告警等（详见 `审查报告-wb-fl-linkgroup-R1` 修复批）。
